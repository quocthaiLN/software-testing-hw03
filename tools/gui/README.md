# Login GUI test runner

Implements retained initial checklist IDs GUI-A-001 through GUI-A-016. It tests the existing SUT without changing application logic. Uses bundled Playwright and Microsoft Edge headless; this is Task 1 evidence, not the required Chrome/Firefox/mobile matrix for Task 3.

## Flow and ownership

1. `playwright.config.mjs` requires a unique GUI_RUN_ID, selects Edge at `/usr/bin/microsoft-edge`, fixes viewport 1280×800 and runs one worker without retries. It refuses an ID whose evidence folder already exists, preserving earlier runs.
2. `fixtures/index.mjs` opens a fresh LoginPage for each test. Authentication scenarios call `makeUser()` to register disposable local demo users through the API. They do not lock the shared default accounts.
3. `pages/LoginPage.mjs` owns input/button/error locators and fill/login actions. CSS fallback for the two inputs is documented because the current form labels are not associated with inputs. Assertions remain in `tests/login.spec.mjs`.
4. `test-data/users.mjs` owns public dummy values. Tests check headings/forms/navigation/authentication/lockout against the retained checklist. GUI-A-016 polls the specified elapsed-time condition and retries correct login after more than 30 seconds.
5. After each test, raw observed UI text, input metadata, URL and browser version are attached. Failed tests receive native screenshots. Threshold/duration scenarios also attach numeric observations. JSON and screenshots are execution evidence; they are not student-authored bug reports.

## Run

Start the SUT using the homework environment guide. From `hw03`, with the bundled node_modules link available, choose a **new** ID for every invocation:

```bash
GUI_RUN_ID=T1A_YYYYMMDD_NN node node_modules/playwright/cli.js test --config tools/gui/playwright.config.mjs
```

An exit code of 1 can mean failed assertions, not an unavailable SUT. Inspect `submission/evidence/gui/<run>/playwright-results.json` and attachments before classifying it. Do not rerun the same ID or overwrite earlier evidence. Source/config corrections require a new run ID; retain the original run and explain the correction.
